# ESP32-S31 compiled verification probes

These packages build retained Rust entry points for instruction- and
effect-level comparison with caller-owned vendor artifacts. The probes depend
on production driver crates, but no production crate or HIL firmware depends
on the probes.

Build and validate the comparison images from the repository root:

```console
cargo vendor-check probes --chip esp32s31
```

The images `oer-firmware-probes-esp32s31-radio` and
`oer-firmware-probes-esp32s31-register` are built for
`riscv32imafc-unknown-none-elf` by `cargo fw probe`, copied into
`target/verification/esp32s31/`, and each image's `.blobray.probes` catalog is
validated against its executable symbols. `cargo fw probe <package>` alone
builds one image without that validation. The probe build sets
`cfg(oer_probe)` into `target/fw-probe`; no production crate reads it.

## The public API alone

A comparison probe reaches the hardware only through the production crates' public
API: production has no probe constructor, validation module or item only a
probe uses. Each image's `open_probe_session_init` entry takes the reset
root once (`Root::take`, `Root::into_runtime`), splits the radio once over
the platform clocks (`RadioHardware::split::<ChipClocks, _>`) and brings
Wi-Fi up through its public client path (`WifiCold::power_up`,
`enable_clocks`, `into_running`). It holds the owners in a `ClaimCell` of the
image for the verifier session and returns zero, or a typed reason as a
nonzero word; every later entry borrows the owner it needs from it and
rejects without a write when the session did not start. No entry claims a
register again. The scenarios run the session entry first, as a setup of
which nothing is compared (`tools/vendor/scenarios-esp32s31/src/session_entry.rs`).

`esp32s31-radio` covers the coexistence timer bank and core release, the
Wi-Fi MAC leaves the public MAC API exposes (receive policy, CCMP
association, interface addresses, AP and STA TSF, beacon filter, RX reload
status, the normal-rate selector), the PHY command memory, the calibration
leaves on the shared PHY and the software-frequency harness edge.
`esp32s31-register` covers the role receive policy. Leaves that need an
item the public API lacks are not built; the list is kept with the task
notes outside this repository.

## Declaration and validated build

Use the [shared probe compiler](../../tools/vendor/scenario/HARNESS.md) to declare each
entry once with `oer_probe_macros::probe!`. It generates the C export, linker root
and embedded ABI catalog. Simple adapters use `=> expression;`; complex adapters
retain explicit bodies. Symbol names and C projections are the boundary the
scenarios select.

Every comparison ELF contains `.blobray.probes`. Build scripts derive roots from the same
Rust declarations used by the macro frontend; there is no retention list to edit
when adding an entry. The catalog is part of the captured production artifact.

`ets_delay_us` and the post-delay barrier in the software-frequency adapter retain
their optimization semantics. The owned software-frequency probe lets the
harness-edge scenario
(`tools/vendor/scenarios-esp32s31/src/engine/harness_edges.rs`) check an ordinary
call to the captured ROM veneer, its tail transfer to `ets_delay_us`, and the
two-microsecond modeled delay. These checks concern software boundaries, not
physical timing.

No entry adapter exists: Blobray enters every vendor root and production probe
directly. Explicit words fill the argument registers and the stack, and a root's
callee-saved registers start at zero, so evidence and effect contracts bind the
real functions.

## PAC-only hardware facts image

`oer-firmware-probes-esp32s31-facts` is a standalone SRAM image for short
silicon facts that the production HAL does not expose. It takes the PAC once,
uses only typed PAC accessors for MMIO and `oer-riscv` for architectural
operations, and never runs hart 1. It has no HAL dependency. Production crates
have no knowledge of this image or its probe selection. Build it with
`cargo fw probe oer-firmware-probes-esp32s31-facts`.

Its entry initializes its own SRAM stack and BSS. It includes the current
runtime's trap assembly, without linking the runtime, for comparable interrupt
entry/exit overhead. Controlled admission entry stubs measure the immediate
threshold-raise boundary, including the interrupted instruction's PC.
Linker geometry and vectors derive from chip facts.
The single registry in `src/image.rs` selects bounded experiments. A ROM RAM
loader starts the image; JTAG publishes commands and reads result words under a
`cargo stand lease --board s31-a`. Commands retain the session's one PAC claim;
no raw peripheral reads or writes by the host substitute for PAC accesses.
The facts image is the sole probe admitted by the layer test to depend on PAC.
