# Lessons of the predecessor's analysis tools

Carried from the predecessor's issue discussions as written; unverified unless a line says otherwise.

- (13) trace clock stays the link-time symbol; K1 one declared capacity + one margin per stack, `stack-coverage.toml` deleted (file still at `firmware/platform/espressif/stack-coverage.toml`); K2 "no analyzer-only code; typed structures welcome", typed static IPC entries; K3 one ELF reader; K4 ROM linker script generated from the ELF; K6 one trap-entry check. Facts for re-measurement: station IRQ stack bound 1056 B (hart 0) / 992 B (hart 1) of 31744 usable, conditional on the executor invariant; `radio_task` resolved part 168,624 B vs 192 KiB; ten ISR-reachable functions in PSRAM (`embassy_executor::raw::waker::wake`, `core::panicking::*`, `expect_failed`, `unwrap_failed`, `panic_already_borrowed`, `esp_sync::panic_lock_not_reentrant`, `rust_begin_unwind`, `panic::record`, `pre_system_reset`); KCFI only via custom target JSON + `-Zbuild-std`, dropped (footprint); MIR driver 1695/1793 indirect sites resolved, image byte-identical; 514/518 `core` functions equal with `-Zinline-mir -Zinline-mir-preserve-debug -Zmir-strip-debuginfo=locals-in-tiny-functions -Cforce-frame-pointers=non-leaf -Cembed-bitcode=yes`, opt-level 3, one CGU; fat LTO reportedly blocks per-function `.isr.text` placement (to re-verify: current `sections.x` does place `core` functions); analyzer budget 10⁹ work units, 512 MiB, 5 min (largest image ~240 MB).
- CLIC run-level restore; handler FPU off; `.rwtext` PMP alignment; Zcmp workaround on chips ESP-IDF names; esp-pacs fixes (S31 GPIO matrix reset-value typo, `USB_UTMI`, 18 S31 / 6 C5 interrupt sources added, C5 GPIO input matrix of 117, C5 `LP_APM0`, C5 `TEE`/`LP_TEE` clock-gate offsets); C5 MWDT `wdt_conf_update_en`, USB-JTAG FIFO overrun, SYSTIMER `CONF_LOCK` upstream defects. Hang watchdog evidence: a stalled hart's `sp` lies on PSRAM task stacks (0x5038xxxx); interrupt stack at 0x2f0207f0.
- **tool survey.** cargo-call-stack 0.1.16 does not run on the toolchain and has no RISC-V machine-code analysis; Charon drops async bodies; CFI/KCFI is "not supported for this target" (works only through a custom target JSON and `-Zbuild-std`, and changes the image); Rupta needs nightly-2024-02 and up to 128 GB; no decoder covers the full S31 set (F, Zb, Zcb, Zcmp), Capstone only as a cross-check; `.llvm.callgraph` is clang-only. Simulation: Blobray's executor stops about 1 400 instructions into `runtime_main` on the first hardware-valued branch; QEMU and Renode do not support the S31; esp-emulator is early beta.
- "The analyzer does not force the firmware to change. When its preconditions do not hold, it still reports, marked partial, with warnings." Close to main's "Probes stay non-invasive" but not the same statement.
- Active Probe Requests need an absolute TX deadline covering publication, completion, cleanup and the return home; `cancel_published` gives no bound. Never retune or resume AP TX while an admitted off-channel attempt still owns the hardware." - "Passive search has no bounded discovery time: equal beacon intervals can keep an upstream beacon outside every window. An unknown hidden BSSID cannot be identified from a beacon." - Window figures: "dwell ≤ 20 ms, guard 2 ms before the next TBTT; skip a window that has expired or reaches the next TBTT; dense 30 s, then about 1/s." - Qualification plan : "capture CTS-to-self and check its Duration/NAV against the request; departure and return against the absolute window end and the next TBTT; AP beacon/TSF continuity, keys and downstream data across repeated visits; late or refused windows; failed return (no AP TX on an unknown channel); tolerances fixed before the run."

- **LaunchGate conditions.** The lifecycle cell's waker is lock-free (atomic-waker on native CAS). embassy_sync `AtomicWaker` is excluded because it takes a critical section. `Launch<'_>` is taken by value at every launch: head, successor, retry relaunch, A-MPDU publish. Abandon returns only after every checked launch has ended. - Unverified: M portable/adapters/embassy/net/src/owned.rs uses embassy_sync `GenericAtomicWaker`.
- "TBTT events from the POWER interrupt are lossy; the driver times TBTT wakes itself and latches the TSF at the event."
- Rejected: critical_section Mutex, RawMutex, and backend self-refill.
- **f / g / h, arbiter and station.** - Every cancellation path (NotReady, Late, Switch, Released) returns the token via `withdraw_plan`; the Late rule uses `RETUNE_UNPLANNED`. - Absences without retune (`AirNotice::Absence`, doze): the gate closes at `from` and reopens at `until` on home; PM=1/0 Nulls; the AP keeps CTS-to-self usable; coexistence can shorten scan dwell. - The power-save decision emits `Awake{until}` or `MayDoze{until_tbtt, group_wake}`. - : step the search-absence phase across BI with bounded, tested coverage. - : a TBTT schedule only in a station TSF already taken, with a host regression test.
- **S31 backend plan.** - Retune while Enabled goes through a closed gate and an affine `ChannelReady`. RX metadata carries the channel of its receive generation. A transition that cannot confirm the channel keeps the gate closed and faults the port. The deadline comes from S31 measurement only, because the ROM READY poll is unbounded. Retune is serialized with tracking, scan and absence. - `Drained` means every terminal of admitted work was delivered. `Abandon::Stopped` and ordinary faults end in Drained; Unconfirmed and accounting corruption end in Quarantined. - Measurement profile: provisional large `DrainBound`/retune bounds, fail-closed. A HIL diagnostic records the maximum driver step, ISR and retune under load, across channels and temperatures, at production CPU frequency. Measured maxima plus margin replace them before S31-2; no measurement-profile image ships. - AP DTIM count comes from the typed AP `TsfSample` (TBTT at multiples of BI × 1024 µs), not from beacon terminals and not from the vendor `/100 * 0x19000` normalization. Beacons are scheduled by a software timer on AP TSF; `TBTT_1` interrupts come later. - The beacon and probe-response timestamp is backend-owned; hardware insertion is unproven (the vendor buffer holds `hal_now` low word before TX). A HIL test with distinct SRAM, AP TSF and local time, a delayed beacon, AP-only and STA+AP, after restart and retune, and around the low-word carry. - Carried requirements: - : STA+AP CTS-to-self Duration/NAV and return before window end and next TBTT, tolerances declared before the run; - : the TSF test cites the IEEE reference point and separates FIFO wait, MAC access, sampling and air time; - : non-HT WPA2 without HT/A-MPDU dependency; - : a lost port ends the station as `Faulted(reason)`; dropping the publisher closes the stream; - : `AttemptFailed`/`RetryExhausted` on the product stream; - : the backend is generic over `oer-base-network`. - : the S31-1 backend and the S31-2 composition remain unbuilt. - : planned S31 evidence: `AckEvidence` = SNR always; `BlockAckEvidence = Measured(snr) | StatusWithoutSample{status}`; `AirDenied = Infallible`.
- **observer.** "A backend and actor observer type parameter, `` in the product (empty `#[inline(always)]`), `&self`, never blocks, allocates, locks or panics; one SPSC ring per context with an overflow count; the HIL composition equals the product composition except the observer." Events: Published{ac, ticket, frame}, Step{kind, start, end}, Retune, Drain, IsrLatch; for the actor, Admitted, Answered, calibration begin/end, grant/refusal/notice.
