# ESP32-S31 platform data

| File | Holds | Read by |
| --- | --- | --- |
| `chip.toml` | the chip layer of the [chip facts](../../espressif/facts/README.md): properties, flash map, address map with its attributes, boot chain, harts, revisions, reset cause; the image registry (`[hil]`, `[packages]`, `[[probe]]`) | `oer-espressif-facts`, `oer-chip-profile` and everything that loads a profile |
| `rom-rev0.toml` | the ROM layer: the revision 0 mask ROM (its ELF pin, symbol script, summaries, forbidden code) and what it uses of the internal SRAM | `oer-espressif-facts` |
| `modules/esp32-s31-wroom.toml` | the module layer: the flash and PSRAM fitted with the chip | `oer-espressif-facts` |
| `boards/esp32-s31-function-coreboard-1.toml` | the board layer: the board that carries the module | `oer-espressif-facts` |
| `stack.toml` | the chip's stack policy, which the HIL policy extends | `oer-chip-profile` (`policy`), the image stack check |
| `partitions/applications.csv` | the application partition table | the image pipeline (`chip.toml` `[flash]` names it) |
| `rom-functions.toml` | reviewed summaries of the ROM functions the images call | the stack analysis (`rom-rev0.toml` `[rom]`), the provenance check |

The linker scripts are in `chips/esp32s31/layout/linker` and
`chips/espressif/staged-layout/linker`; the boot is described in
[staged bootstrap](../../espressif/staged-bootstrap/README.md) and
[stage-two runtime](../../espressif/staged-runtime/README.md).

`chip.toml` `[interrupts] harts` is the sole HP-hart cardinality, with
`boot-hart` naming primary initialization. SOURCE: ESP-IDF 4d80c1b2
`soc/esp32s31/include/soc/soc_caps.h`, `SOC_CPU_CORES_NUM`.
The facts derive `properties.cores` for host consumers; an explicitly supplied
counter must agree with the list. Guards cover every listed hart exactly once.
The register root's `hart-facts` points here: `harts` and `secondary-harts`
size register, field and instance families. PAC `HARTS`, `Hart::ALL`,
`Hart::SECONDARIES` and `BOOT_HART` are generated by the same facts renderer.
`Hart::new` refuses unknown raw IDs without truncation; `Hart::constant` checks
fixed IDs at monomorphization. These are identities, not launch permits.

## Secondary-hart containment

The bootstrap contains every secondary and clears its indexed ROM boot word.
The public HAL exposes no start or release operation. Both staged entries stop
non-boot harts before Rust memory access. Current images declare secondary
task and interrupt stacks as zero; their linked-image checks reject secondary
starters, routes and storage and confine hart-local critical-section entries
to declared hart roots. The symbol inventory does not identify inlined launch
code. SOURCE: `hal/src/boot/soc.rs::contain_secondaries`, staged entry code,
and the image checks' critical-section and unused-stack gates.

The local CLIC is context-relative; indexed matrix/boot-word families do not
grant another hart's execution authority. HAL explicitly selects MNLBITS.
SOURCE: `HW1_S31_CLIC_20261026` in `registers/evidence/hw-interrupts.toml`;
inherited rev0 MNLBITS is one, independently of the header reset value.
