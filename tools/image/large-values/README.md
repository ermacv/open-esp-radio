# Large MIR values

`oer-tool-image-large-values` is the pinned compiler's host wrapper, using
`rustc-dev` from `rust-toolchain.toml`. `cargo fw` and HIL builds install it
through `RUSTC_WRAPPER` in `oer-image-build::compiler::configure`.

The filter is the exact list of workspace package manifests from
`cargo metadata`, matched against Cargo's `CARGO_MANIFEST_DIR`. It also
requires the image target and code generation. Dependencies outside the
workspace, build scripts, proc macros, compiler probes and type checks run
the original rustc with unchanged arguments. `RUSTC_WRAPPER` preserves
Cargo's artifact namespace; `RUSTC_WORKSPACE_WRAPPER` changes artifact hashes
and can change ELF bytes.

The wrapper reports every codegenerated monomorphized instance's locals,
temporaries, arguments and return slots, and Copy/Move/constant arguments at
direct and indirect call sites, with target layout greater than the image
stack policy's `max_move_bytes`. Each record has the full instance name with
generic arguments, role, MIR place, concrete type, bytes and source span.
Macro spans point to the outer invocation. Instances shared between codegen
units are visited once. Static allocations are not MIR locals; references
to them are small. A large by-value temporary used to initialize static
storage is still a local and is reported.

MIR bodies and layouts use `rustc_public`. `src/bridge.rs` alone imports
private compiler crates: session startup, codegen enumeration and macro
call sites, which the public Span API on the pin cannot supply. Missing
bodies and inspection errors are explicit in the report. The crate forbids
unsafe code. The root Cargo configuration enables compiler imports for this
host crate alone; images retain their existing bootstrap setting and flags.

This measures values before LLVM. It cannot measure final machine stack
frames, call-chain bounds, C/assembly, or code not codegenerated by a wrapped
workspace crate. LLVM can remove reported values or create larger frames
through inlining and spills. Foreign generic code is inspected when an
instance is codegenerated in a workspace crate; nonworkspace dependencies
otherwise remain unchecked. Reports describe codegen units, including code
that linking subsequently discards.

Each artifact retains a schema-2 sidecar in its rustc output directory:
`<crate><extra-filename>.large-values.json`. It includes the compiler's
metadata hash, exact workspace manifest, reporting-tool identity and limit.
Binary sidecars also carry the final ELF's SHA-256, verifying their contents after compilation. The pipeline resolves Cargo's
unhashed uplift to the hashed artifact by file identity (device/inode),
including byte-identical cached feature variants. Library reports follow hashed rlib/rmeta artifacts.

The pipeline reads Cargo artifact messages, including Fresh units, to
assemble `large-values.json` and `large-values.txt` beside the image. Missing
or stale facts invalidate only the affected workspace packages' target
fingerprints and rerun Cargo once. Any remaining absence is explicit in
coverage and stderr. Findings and sidecar-write errors do not change the
compiler verdict. JSON has a versioned image envelope with per-crate
`facts`; further compiler fact collections can extend those objects.

`compiler::configure` supplies `OER_LARGE_VALUES_WORKSPACE` (JSON manifest
paths), `OER_LARGE_VALUES_TARGET`, `OER_LARGE_VALUES_LIMIT`, and
`OER_LARGE_VALUES_DRIVER_ID` to its Cargo command. The executable accepts the
original rustc path followed by its arguments. Its host build is separate
from the image cache at `target/fw/large-values-driver/`.

Compiler fixtures run the pinned toolchain in temporary directories:

```console
cargo test -p oer-tool-image-large-values -p oer-image-build -p oer-test-layers
cargo clippy -p oer-tool-image-large-values -p oer-image-build --all-targets
```
