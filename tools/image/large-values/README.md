# Large MIR values

`oer-tool-image-large-values` is a host compiler wrapper for the exact
`rust-toolchain.toml` pin, including its `rustc-dev` component. Its entrypoint
accepts the original rustc executable followed by rustc's arguments.

With `OER_LARGE_VALUES_TARGET` set to the image's Rust target and
`OER_LARGE_VALUES_LIMIT` set to its stack policy's `max_move_bytes`, it reports
codegenerated monomorphized instances. Host compilations, compiler probes
and type checks run the original compiler. Findings and report-write errors
do not change the compiler's exit status.

Reports contain locals, temporaries, function arguments, return slots and
Copy/Move/constant arguments at direct and indirect call sites whose target
layout exceeds the limit. Instance names include generic arguments; each
record gives the role, MIR place, type, bytes and source span. Macro spans
point to the outer invocation. Instances shared between codegen units are
visited once. Static allocations are not MIR locals; references to them are
small. A large by-value temporary used to initialize static storage is still
a local and is reported.

MIR bodies and layouts use `rustc_public`. `src/bridge.rs` alone imports
private compiler crates: it starts the session, enumerates codegen
instances and obtains macro call sites, which the pin's public Span API
cannot supply. Missing bodies and layout errors are recorded explicitly.
The crate forbids unsafe code. `.cargo/config.toml` enables compiler imports
for this crate alone in host builds; image builds retain their own bootstrap
setting.

This measures values before LLVM. It cannot measure final machine stack
frames, call-chain bounds, C/assembly, or code not codegenerated in the
wrapped workspace compilations. LLVM can remove reported values or create
larger frames through inlining and spills. A workspace wrapper leaves
nonworkspace dependencies unchecked; their generic code is inspected when
an instance is codegenerated by a wrapped workspace crate.

Library sidecars are written in rustc's output directory with their artifact
hash (`<crate><extra-filename>.large-values.json`). Binary sidecars use the
unhashed crate name in the parent directory. The image pipeline does not
currently invoke this wrapper or aggregate its sidecars.

Compiler fixtures run the pinned toolchain in temporary directories:

```console
cargo test -p oer-tool-image-large-values
cargo clippy -p oer-tool-image-large-values --all-targets
```
