# Bluetooth LE reference model

`oer-bluetooth-le-model` implements the LE port's DTM 1M profile on virtual
time. It is a host reference backend, with allocating storage and no executor
or real-time waits. Each installation registers one P2 owner and separate
queue backing through the common radio lifecycle.

`Environment` is separate from the port backend. Its owner supplies a nonzero
packet period, advances virtual time and chooses propagation loss. Independent
radios receive matching PHY/channel test packets generated by a transmitter;
End returns an explicit saturating packet count. Loss phase persists across
time advances. A quiet transmitter generates no packets. The period is an
input of the test profile, not a claimed controller timing guarantee.

The backend admits commands synchronously, records the original admission
instant and drives one publication per P2 poll independently of P1 event
reads. Body-loaned capacity and session owners are converted into complete
owned queue values using private BodyLoan authority. Epoch discontinuities
cannot publish old requests. A new installation has fresh capacity and empty
queues; abnormal teardown retains the actual queued and quarantined owners
until the local modeled hardware world is ended.

The `test-support` feature exposes `conformance::ModelFixture`. It runs the
shared portable suite against registered backends, including two independent
DTM radios, exact propagation loss, refusal, FIFO cancellation, dropped event
waits, disable, rejection, fault and reinstall. Traces capture actual returned
session/context identities. 2M remains a Hardware case and is reported as
unsupported by this profile. Injected publication-boundary stimuli are distinct
from propagation loss and carry no claim of hardware execution.
